# Driving Mood 무드 분석과 차량 경험 설계

무드 키워드 추출 알고리즘과 Pleos Connect 연동 계획

기준일 2026년 10월 24일 · 현재 앱 0.3.0 · 제품 및 기술 설계

## 1 제품의 핵심과 목표

Driving Mood의 핵심은 주변 환경과 운전자 맥락에서 무드 키워드를 추출하는 공통 분석 엔진이다. 음악, 차량 실내조명, 근처 갈 만한 곳 추천은 이 결과를 사용하는 확장 기능이다. 최종적으로 운전자의 현재 감성 맥락과 원하는 분위기를 이해하고 다양한 차량 경험에 연결하는 앱을 목표로 한다.

프로토타입은 30초·60초 영상 촬영, 저장 영상 분석, 완료음, 무드 결과, 음악 추천·조명 미리보기를 하나의 흐름으로 연결한다.

카메라는 도시의 빛과 공간을 관측한다. 내비게이션은 주행·경로 맥락을 제공하고, 시간·날씨는 장면 해석을 보완한다. 운전자의 선택과 피드백은 같은 풍경을 사람마다 다르게 느끼는 차이를 반영한다. 환경의 분위기, 운전자가 직접 알려준 현재 기분, 앞으로 원하는 분위기를 각각 구분해 다룬다.

| 구분 | 현재 0.3.0 | 최종 개발 방향 |
|---|---|---|
| 공통 분석 | 공용 점수기와 요소별 기여 원장 | 규칙 검증과 개인화 |
| 영상 | 30/60초 녹화·프레임 분석과 관측 누적 | 장소별 조명 구별과 경량 모델 최적화 |
| 개인화 | 원하는 분위기·선호 장르·곡 태그 | 현재 기분·수정 피드백과 개인화 학습 |
| 활용 | 로컬 음악 추천·재생과 조명 미리보기 | 음악·실내조명·주변 장소 추천 등으로 확장 |
| 차량 연결 | 휴대폰에서 동작 | Pleos 내비게이션 입력과 조건부 조명 제어 |

## 2 현재 파이프라인과 알고리즘

![관측 영역과 기여 점수, 시간 구간 누적 파이프라인](assets/driving-v2/scoring-pipeline.png)

분석 버튼으로 30초 또는 60초 영상을 녹화하며 위치·날씨를 병행 확인한다. 저장이 완료되면 영상의 실제 시각을 기준으로 1초마다 대표 프레임을 분석한다. 결과 확정 후 완료음을 내고 음악·조명 프리셋에 연결한다. 임시영상은 분석·취소 후 삭제한다.



사람의 기여, 빛의 면적과 색 분포, 하늘·날씨 근거를 각각 계산한다. 색감·밝은 면적의 강도와 측정 품질을 분리하고, 각 영역의 실제 픽셀량으로 기여를 배분한다. 공간 분포와 시간에 걸친 지속성을 평가해 음악 후보를 만든다.

| 계산 항목 | 프레임별 규칙 |
|---|---|
| 따뜻한 색감 강도 | 70 × 빨강·노랑 픽셀의 채도 합 ÷ 전체 픽셀 수 |
| 차가운 색감 강도 | 70 × 청록·파랑 픽셀의 채도 합 ÷ 전체 픽셀 수 |
| 밝은 면적 강도 | 35 × 중복 없는 관측 픽셀 수 ÷ 전체 픽셀 수 |
| 사람 기여 | 55 × min(검출 수 ÷ 5, 1) × 측정 품질 |
| 영역별 배분 | 실제 영역의 픽셀량·채도 합에 따라 기여 배분 |

색 해석은 화면 점유율 0.1% 이상과 색 분류 가능 범위 절반 이상을 확인한다. 한 색군의 채도 비중 60% 이상을 주된 색감, 두 색군이 각각 20% 이상·합계 60% 이상이면 혼재로 해석한다. 시각적 활력은 화면 점유율 2%와 2×2 중 두 구역 이상의 분포를 사용한다. 이 조건들이 촬영 기간의 절반 이상 지속되는지 평가하는 초기 규칙이다.

시간 구간별 기여를 평균하고, 색·빛의 주요 조건이 촬영 기간의 절반 이상 지속되는지 확인한다. 사람·하늘·날씨의 점수와 빛의 면적 강도는 별도 항목으로 표시한다. 세부 식과 조건은 [점수 설계](MOOD_SCORING.md)에 정리했다.



근거: `SceneAccumulator`, `SceneMoodScorer`, `SceneObservationBuilder`와 [점수 설계](MOOD_SCORING.md), [검증 기록](../VALIDATION.md).

## 3 공통 무드 엔진의 목표 구조

![공통 무드 엔진과 다양한 활용 기능의 설계](assets/target-architecture.png)

0.3.0은 순수 Kotlin 점수기와 관측 창을 분리해 앱과 데스크톱이 같은 규칙을 호출한다. 입력 제공자는 시간·날씨·영상 관측을 전달하고 음악과 조명 미리보기가 같은 결과를 활용한다. 아래의 확장 MoodState와 차량 출력 구조는 목표 설계다.

| 제안 출력 필드 | 의미와 사용 원칙 |
|---|---|
| environmentKeywords | 따뜻한 색감, 낮은 조도 등 관측에서 얻은 분위기 |
| driverReportedMood | 운전자가 직접 선택한 현재 기분과 입력 시각 |
| desiredMood | 운전자가 원하는 분위기이며 현재 기분과 별개 |
| resolvedKeywords | 입력 품질과 사용자 선택을 반영한 공통 무드 키워드 |
| evidence와 quality | 출처·시각·누락·측정 품질·해석 근거를 함께 전달 |
| status와 validity | 유효·부분 가용·미확인 상태와 결과의 유효 기간 |

최종 키워드는 사용자 선택을 우선하고 환경 관측을 보조 근거로 쓴다. 예를 들어 밝은 상권에서도 ‘차분하게’라는 목표를 유지할 수 있다.

개인화는 현재 기분·좋아요·수정 피드백에서 시작한다. 선택 이력의 저장과 초기화 기능을 제공하고 개인화 전후의 추천 적합도를 비교한다.

음악 어댑터는 키워드를 곡 태그에, 조명 어댑터는 프리셋에 연결한다. 장소 추천은 원하는 분위기와 위치·이동 거리·경로 이탈 정도를 함께 사용한다.

‘원하는 분위기’는 환경 결과와 별개로 음악에 우선 반영한다. 곡의 가중치는 장르 일치에 3, 환경 태그 일치에 2, 선택 목표 일치에 6을 기본값 1에 더한다. 최근 곡의 반복을 줄이고 가중 무작위로 후보를 정한다. 선택 변경은 완료된 관측으로 추천만 갱신한다.

## 4 영상 모델과 맥락 결합 전략

경량 모델로 차량·도로·건물 영역을 구분하고 해당 영역의 빛과 색을 측정한다. 내비게이션·날씨를 별도 입력으로 결합해 설명 가능한 규칙으로 무드를 해석한다.

| 모델 또는 방법 | 맡길 역할 | 검토 상태 |
|---|---|---|
| EfficientDet Lite0와 픽셀 규칙 | 사람 관측·차량 제외·색감 측정 | 0.3.0 APK |
| YOLO26n sem Cityscapes | 차량·도로·건물 구획 | 데스크톱 예비 비교 |
| YOLO26n sem ADE20K | 창문·간판 등을 포함한 장면 분할 | 데스크톱 예비 비교 |
| YOLOE26n 및 s | 지정 개념의 영역 후보 검출 | 데스크톱 예비 비교 |
| 대형 모델 | 필요시 오프라인 표본 검토·주석 보조 | 런타임의 필수 구성 아님 |

YOLO26의 Cityscapes·ADE20K 의미분할을 비교했다.[6] 실제 주행 6개·4,757프레임에서 차량 실내·반사광 오분할, 도로 표지판 혼동과 색감 채택률 문제를 확인했다. [주행 실험 자료](DRIVING_DEMO.md)에 원본·분할·계산 결과를 보존했다.

모바일 전환에서는 가중치 크기와 함께 출력 텐서·후처리 메모리를 평가한다. ADE20K의 640×640×150 FP32 출력은 약 234.4 MiB이므로, 후처리 결합·해상도·양자화를 함께 검토한다.

모델 채택 기준은 야간·비·터널·고속도로의 오류, 단말 지연·최대 메모리·발열, 변환 가능성과 라이선스다. Ultralytics 후보의 AGPL 또는 상용 조건을 적용 범위에 맞춰 확인한다.

내비게이션에서는 현재 도로 종류, 경로 옵션, 차량 진행 방향과 카메라 시선 방향을 구별해 사용한다.

## 5 Pleos Connect 연동 가능성과 조건

Pleos Connect는 Android Automotive 기반 차량 인포테인먼트 플랫폼이다.[1] NaviHelper와 Vehicle SDK의 입력·제어 경로를 활용하고, 프로젝트 권한과 차종별 지원 범위를 확인한다.

| 연결 항목 | 공식 문서에서 확인한 내용 | Driving Mood 적용 판단 |
|---|---|---|
| 내비게이션 | 현재 위치·경로 상태·TBT 등 이벤트 제공 [2] | 입력 어댑터 개발 가능성 확인 |
| 도로 의미 | 경로·안내 정보와 현재 도로 분류는 다름 | 도로 종류 필드와 매핑 확인 필요 |
| 실내조명 | Light 도메인에 앰비언트 색상·밝기 제어 경로 [3] | 조건부 제어 대상으로 설계 |
| 제어 사용 권한 | 사용 신청 안내는 Vehicle Control을 준비 중으로 표시 [4] | 프로젝트 접근 상태를 별도 확인 |
| 차종별 지원 | checkXXXCapabilities로 가용성 확인 [5] | 지원 범위·값·실패 처리를 동적으로 확인 |
| 차량 카메라 | 본 조사에서 외부 앱용 원본 영상 경로 미확인 [7] | 휴대폰 카메라로 시작 |

Light API의 `setAmbientLightBrightnessColor`, `setAmbientLightBrightness`와 capability 메서드, Virtual Console의 앰비언트 상태 항목을 연동 후보로 검토했다.[3][8]

조명 어댑터는 지원·권한 확인 → 상태 조회 → 제어 요청 → 결과 확인 순서로 구성한다. 미지원 환경에서는 프리셋 미리보기를 제공하고 사용자의 수동 조작을 우선한다.

내비게이션 연결은 공식 샘플을 참고해 이벤트·누락·재연결을 검증한다.[9] 적용 대상은 필요한 기능이 지원되는 Pleos Connect 차량이다.

## 6 입력에서 차량 경험까지의 동작 설계

현재 프로토타입의 흐름은 **30초·60초 촬영 → 영상 분석 → 완료음 → 무드 결과 → 음악·조명 미리보기**다. 이후 차량 연결에서도 같은 입력·출력 구조를 확장한다.

1. 입력의 관측 시각·수신 시각·출처·가용 상태를 기록한다.
2. 프레임 품질과 영역 마스크를 검사하고 차량광·반사광의 영향이 큰 장면은 색감 기여를 낮추거나 제외한다.
3. 환경 키워드 후보를 만들고 내비게이션·날씨와 대조한다. 근거가 충돌하면 미확인 또는 제한된 결과를 반환한다.
4. 운전자가 선택한 현재 기분과 원하는 분위기를 별도로 반영한다. 명시적 원하는 분위기를 자동 환경 추정보다 우선한다.
5. 여러 관측의 지속성과 유효 기간을 검사해 키워드를 안정화한다. 최소 유지 시간과 변경 조건을 두어 화면·곡·조명이 짧게 반복 전환되는 일을 줄인다.
6. 같은 MoodState를 음악과 조명에 전달한다. 음악은 다음 곡에 반영하고, 조명은 허용된 범위에서 점진적으로 바꾼다. 사용자 취소·수동 변경 시 자동 출력을 멈춘다.

| 예시 상황 | 공통 무드 해석 | 출력 예시 |
|---|---|---|
| 따뜻한 도시 조명과 차분함 선호 | 따뜻한 색감과 차분한 목표를 함께 유지 | 잔잔한 곡 후보와 낮은 밝기의 선호색 |
| 비 오는 고속도로 | 차량광 기여 제한과 원하는 분위기 우선 | 안정적인 곡 후보와 유지되는 조명 |
| 밝은 상권이지만 휴식을 선택 | 밝은 환경과 휴식 목표를 분리 | 휴식 목표에 맞춘 음악과 조명 |
| 카메라 또는 내비게이션 중단 | 남아 있는 유효 입력으로 부분 가용 | 사용자 프리셋 유지와 출처 안내 |

조명 출력은 사용자 선호를 반영한 실내 앰비언트 프리셋으로 시작한다.

주행 화면은 짧은 키워드와 간단한 조작으로 구성하고, 상세 분석은 별도 화면으로 제공한다. CarUxRestrictions와 내비게이션 오디오 우선순위를 적용한다.[10]

## 7 단계별 개발 계획

0.3.0은 요청형 녹화·분석 흐름과 실제 픽셀 분포, 요소별 기여를 연결했다. 다음 단계는 작은 간판·넓은 조명 관측의 모바일 적용과 시간·날씨·공간에 따른 장면 해석이다.

| 단계 | 작업과 산출물 | 다음 단계 진입 기준 |
|---|---|---|
| 1 공통 무드 계약 | MoodState와 입력·출력 인터페이스 확정 | 현재 음악 동작 보존과 출처·누락 처리 검사 |
| 2 영상 분석 개선 | 경량 모델 비교와 장면별 품질 규칙 | 정답 표본 평가와 대상 단말 지속 실행 |
| 3 감성 피드백 | 현재 기분·수정 기능과 선택 이력 활용 | 사용자 의도 우선과 초기화 동작 확인 |
| 4 내비게이션 연동 | Pleos 입력 어댑터와 에뮬레이터 시나리오 | 실제 필드 의미·연결 중단·복구 검증 |
| 5 실내조명 연동 | 프리셋·기능 검사·제어·수동 해제 | 사용 권한과 대상 차량 상태 확인 |
| 6 통합 검증 | 동일 무드의 음악·조명 적용과 시연 | 오해석·전환 안정성·사용자 적합도 평가 |

공통 엔진은 입력 제공자와 출력 기능을 분리한다. 장소 추천은 검색 결과와 사용자 선택을 거쳐 경로 안내로 연결한다.

차량 통합은 SDK 접근 권한과 capability를 확보한 뒤 에뮬레이터와 대상 차량에서 검증한다.

시연은 6개 실제 주행 소스의 대표 구간을 사용한다. 원본·분석·결과의 3종 영상과 90초 편집본, 객체별 근거를 보여주는 그림·GIF를 구성한다.


장면 해석은 개별 물체의 기여에 시간·날씨·공간·주변 활동의 조합을 더하는 방향으로 확장한다. 시간은 기기 시각을 사용하고, 위치 기반 일출·일몰로 계절 차이를 보완한다. 하늘의 밝기·색과 건물·간판의 빛을 분리해 같은 밝기도 맥락에 따라 다르게 해석한다.

| 장면 조합의 예 | 확장할 환경 무드 |
|---|---|
| 밤·어두운 하늘·여러 네온과 사람 | 활기 있는 도시 분위기 |
| 맑은 낮·푸른 하늘·녹지 | 산뜻함·개방감·청량함 |
| 해질녘·주황빛 하늘·부드러운 조명 | 따뜻함·부드러움 |
| 비·낮은 시야·조용한 거리 | 촉촉함·차분함 |
| 새벽·드문 차량·변화가 적은 긴 주행 | 적막함·단조로움·쓸쓸함 |

운전자가 원하는 방향에 따라 분위기를 이어가는 음악과 기분을 전환하는 음악을 제안한다. 현재 기분과 졸림은 사용자 피드백으로 구별해 다룬다.

## 8 시행착오와 개선 근거

초기 정지사진, 분할 모델 비교, 실제 주행 실험의 원본·출력·설정·측정값을 비교 자료로 보존한다.

| 시험 단계 | 확인한 한계 | 다음 비교의 기준 |
|---|---|---|
| 차량 검출과 색감 측정 | 차량 제외만으로 건물·창문·간판을 분리할 수 없음 | 의미 분할과 관측 영역 연결 |
| 범용·도로 분할 예비 비교 | 필요한 클래스 범위와 도로 장면 적합성이 다름 | 같은 입력에서 차량·도로·창문·표지판 비교 |
| 실제 주행 6개·4,757프레임 | 실내·반사광 혼동과 낮은 색감 사용률 | 오류 원인과 측정 조건을 나누어 검증 |

초기 규칙은 원본 161.928초에서 ‘몽환적인’을 출력했다. 보행자와 상가 조명이 많은 장면을 대표 색조만으로 해석한 한계가 드러났다.

![색감만으로 장면을 해석했던 초기 결과의 한계](assets/driving/color-candidate-example.png)

관측 강도와 품질을 분리하고 작은 간판·넓은 밝은 면을 복구하는 방식으로 개선했다. 대표 분할 오류 4개와 초기 결과는 [시행착오 자료](TRIALS.md)에 보존했다.


의미분할 보조 관측은 같은 6개 영상의 176개 실제 프레임에서 비교했다. 야간 도심에서는 작은 네온·세로 간판과 건물의 넓은 밝은 면이 계산에 연결됐고, 30초 구간에서 따뜻한 빛과 차가운 빛의 혼재·활력 후보가 나왔다. 아래는 그 구간의 3개 대표 장면이다.

![따뜻한 상가 조명과 넓은 밝은 면의 기여](assets/driving-v3/clip-03-000500-report.png)

데스크톱 연구 관측의 결과이며, Android 0.3.0에는 기존 채택 픽셀의 색 분포 보존을 적용했다. [5개 장면과 전체 영역 원장](OBSERVATION_IMPROVEMENT.md)에 비교 수치·입력 해시를 제공한다. 주간 햇빛과 인공 조명, 반사광 구별은 후속 개선 항목이다.

모바일 개발 후보에서도 같은 도로 장면을 Android의 ORT·MediaPipe에 직접 입력했다. 기존 방식이 측정한 446픽셀·1개 영역에서 후보는 2,688픽셀·68개 영역을 관측했고, 작은 간판과 넓은 건물 조명의 따뜻한 색도 점수에 남았다. 측정 격자는 320×180이며, 픽셀 증가량은 관측 범위의 변화다.

## 9 검증 계획과 기대 효과

별도 후보 앱은 자동 검사 261개, 실제 RGB 입력 비교, 30초·60초 녹화·분석과 취소 검사를 통과했다. 의미분할 모델의 공개 배포 라이선스와 Galaxy S25+ 성능 확인을 거쳐 제품에 통합한다. 실제 주행 6개의 후속 [90초 시연](VIDEO_DEMO.md)은 326개 관측 프레임의 영역별 기여와 구간 결과를 보여준다.

0.3.0은 자동 검사 250개와 Android 에뮬레이터 기능 검사 5개, 빌드·Lint·서명·정렬 검사를 통과했다. 30초·60초 실제 녹화 파일의 디코딩·분석과 취소 후 임시영상 삭제, 업데이트 설치를 확인했다. Galaxy S25+ 실기기 성능·환경 API 실통신·Pleos 실차 연결은 후속 검증 대상이다. [검증 기록](../VALIDATION.md)에 실행 결과를 제공한다.

| 검증 대상 | 확인할 지표와 방법 |
|---|---|
| 영상 분할 | 차량·도로·건물·창문·간판의 클래스별 IoU와 누락 사례 |
| 차량광 억제 | 고속도로·정체·젖은 노면에서 잘못 포함된 빛의 비율 |
| 시간 안정성 | 같은 장면에서 키워드가 불필요하게 바뀌는 횟수 |
| 단말 성능 | 전체 처리 지연 p50·p95, 최대 메모리, 발열과 지속 동작 |
| 감성 적합도 | 사용자 자기보고와 제안 키워드의 일치·수정·수락 비율 |
| 공동 출력 | 음악·조명의 무드 일관성, 수동 해제와 실패 복구 |
| 요청형 동작 | 대기 중 요청 0회, 캐시 재사용, 중복 탭·취소·시간 초과 후 수집 종료 |

환경 입력 단독, 내비게이션 결합, 사용자 피드백 결합을 동일 조건에서 비교한다. 평가 자료는 도심·주거지·고속도로·터널과 야간·비·역광을 포함하고, 촬영 원본 단위로 개발·평가 집합을 분리한다.

공통 무드 키워드로 음악과 조명의 분위기를 일관되게 연결하고, 운전자가 적은 조작으로 원하는 환경을 선택하도록 돕는다. 효과는 제안 수락·수정 비율과 직접 선택 대비 만족도로 평가한다.

기분·선호 피드백은 정차 상태에서 간단히 수집한다.
