# 모델 개선 실험 기록

2026년 10월 24일. **0.3.9 앱 분석기에 복합 F2와 YOLO26n 객체 검출기를 적용했다.** 단위검사 350개, 네이티브 정합 검사 2개와 실제 앱 분석기 비용 검사 1개를 통과했다. 최종 서명 APK의 설치와 제품 경로 검사도 통과했다. [배포 검증](../VALIDATION-0.3.9.md) 성공한 항목과 실패한 항목을 함께 기록한다. 실제 차량 주행 영상과 이미지자료들을 바탕으로 장면 다양성을 보강했다.

## 문제와 비교 기준

후속으로 **YOLO와 구조가 다른 모델 계열의 실제 비교**를 진행했다. SegFormer B0/B1, Mask2Former-T, OneFormer-T, DeepLabV3 MobileNetV3, PIDNet-S, SAM2.1 Tiny와 MobileSAM을 동일 주행 입력에 실행했다. 후보별 장단점, SAM 경계 보정의 효과와 분류 오류 전파, 라이선스와 단말 검증 조건은 [별도 비교 기록](CROSS_FAMILY_REVIEW.md)에 정리했다. 아래 F2 배포 결과를 서로 다른 모델 계열의 결합 성과로 소급해 표현하지 않는다.

Driving Mood는 주변 풍경의 색과 빛을 음악·조명 추천에 연결한다. 따라서 도로만 잘 구분하는 것으로 충분하지 않다. 사람과 차량, 하늘, 간판·창문이 서로 혼동되지 않아야 하며, 차량의 밝은 부분을 주변 조명으로 잘못 계산하는 것도 줄여야 한다.

기존 배포 기준은 EfficientDet-Lite0 사람·차량 검출, YOLO26n-sem-ADE20K 장면 분할, 실제 RGB의 빛·색 측정이다. 통합 후보는 객체 검출을 YOLO26n으로, 장면 분할을 F2로 확장한다. 파인튜닝은 실제 수행했지만 학습 실행과 성능 향상은 별개의 문제다. 손실이 줄거나 가중치가 바뀐 사실만으로 개선됐다고 판단하지 않는다.

아래 평균 IoU는 정답 주석이 있는 클래스별 IoU의 평균이다. 같은 원본 RGB와 주석 격자에서 비교했으며, 미주석 픽셀은 제외했다. AI 보조 부분 주석이므로 전체 화면의 경계·오탐이나 실제 감성 정확도를 평가한 수치가 아니다. 기존 영상 평가 자료도 반복 검토 후에는 개발 회귀 자료로 사용한다.

Pilot01은 기존 평가 원장을 재사용했으며 다른 개발 자료의 수치를 추정해 채우지 않았다. 학습기 내부의 320 격자 검증 점수는 체크포인트 선택에 사용했지만 위 원본 격자 평가와 섞지 않았다. A/B/C는 공식 초기 가중치에서 각각 다시 학습했다. C의 규제 강도는 학습 자료만 사용하는 예비 실행으로 고정했고, 예비 실행의 가중치는 폐기했다.

## 실패 결과가 알려준 점

학습률을 낮추는 것만으로는 기존 분류 능력을 보존하지 못했다. BatchNorm 통계를 고정한 B는 다른 영역을 간판으로 잘못 분류하는 경우가 늘었다. 혼합 개발 범위에서 간판 재현율은 62.18%에서 99.03%로 높아졌지만 정밀도는 100%에서 18.72%로 낮아졌다. 이를 간판 인식 향상으로만 소개하지 않는다.

C에서는 혼합 개발 간판 IoU가 62.18%에서 93.18%로 높아졌지만, 별도 영상 회귀의 간판 IoU는 여전히 0%였다. 따라서 특정 장면에서의 개선을 다양한 주행 환경에 일반화됐다고 표현할 수 없다. 창문 IoU는 현재 비교한 모든 후보에서 두 평가 범위 모두 0%여서 해결되지 않은 문제로 남았다. 작은 창문이 축소 입력에서 사라지는 문제, 부분 주석과 클래스 해석, 학습 표본의 불균형을 각각 확인해야 한다.

더 큰 모델도 일괄적인 해결책은 아니었다. n640의 영상 하늘 IoU는 97.87%에서 99.15%로 높아졌지만 사람 IoU는 98.63%에서 73.63%로 낮아졌다. s640은 영상 사람 IoU가 100%였지만 보도 IoU는 62.80%에서 1.70%로 낮아졌다. 이 값들은 제한된 부분 주석의 결과이며 전체 사람·보도 인식률을 뜻하지 않는다.

## 복합 구성을 시험하는 이유

한 후보로 모든 역할을 대체하면 잘하던 영역까지 나빠질 수 있다는 점을 확인했다. 이에 사람·차량은 객체 검출 역할로 유지하고, 하늘과 광원 주변 구조는 해당 역할을 맡는 분석기로 분리하는 구성을 시험한다. 목표는 모델 수 자체를 늘리는 것이 아니라 약한 영역을 보완하면서 기존 판단을 보존하는 것이다.

후속 개발 후보는 기존 분할의 사람·차량·도로·보도·교통시설 영역을 우선 보존하고, 다른 후보의 하늘·건물·창문·간판 결과를 나머지 영역에서 합치는 방식이다. 동일 픽셀을 중복 가산하지 않으며, 사람 검출 박스 수와 의미 분할 면적도 더하지 않는다. 결합 규칙은 새 비교 실행 전에 고정했다. 개발 결과를 본 뒤 설계한 후보이므로 이 비교를 새로운 독립 시험으로 부르지 않는다. 하늘색 측정은 평가한 합성 지도와 같은 하늘 마스크를 사용하며, 기존 하늘이 남는 합집합 성격의 장단점도 평가 대상이다.

F2를 유일한 최종 후보로 선택한 뒤 별도 출처의 이미지 보조 평가를 한 번 수행했다. 평균 IoU 56.58%→57.35%, 간판 IoU 27.04%→33.70%, 하늘 100%→100%, 차량(car) 84.08%→84.08%, 창문 0%→0%였다. 사람 정답은 없어 해당 성능은 평가할 수 없다. 두 담당자가 RGB를 확인한 AI 부분 주석이며, 완전히 맹검된 사람 정답 벤치마크가 아니다. 모델·규칙 선택 후 결과를 확인했고 그 결과로 다시 조정하지 않았다.

F2의 우선순위는 **기존 보호 영역 → n640 하늘 → C의 건물·창문·간판 → 기존 분할**이다. 보호 영역 바깥에서만 후보를 반영한다. C 전체 지도를 채택하지 않으므로 C 단독의 차량 퇴행을 성공으로 바꾸어 기록하지 않는다. [동결 규칙](finetuning03/protocols/fusion-freeze.json)과 [공개 평가 코드](finetuning03/src/replay_f2.py)에 같은 규칙을 보존했다.

광원 분석에는 별도 검증이 필요하다. 간판·창문 클래스와 실제 발광 픽셀은 다르며, 반사·전조등·가로등을 밝기만으로 같은 종류로 처리할 수 없다. 가로등은 도로 조명으로 관측하는 후보를 검토하되, 상점의 활기로 자동 가산하지 않는다.

## Android 통합 검증

방향을 보정한 분석 RGB에서 baseline320·n640·C320 입력을 각각 만든다. 이미 축소한 320 입력을 640으로 늘려 재사용하지 않는다. 모델별 패딩을 제거한 후 같은 분석 프레임 격자에 정렬하고, 합성 지도를 하늘색과 광원 관측에 함께 사용한다. 보조 모델이 실패하면 해당 프레임의 기본 모델 결과로 돌아가며 출처에 이를 남긴다. 이전 프레임 마스크는 재사용하지 않는다.

단위검사 **350개, 실패·건너뜀 0**을 확인했다. Android 15 x86_64 에뮬레이터의 [네이티브 검사](../../app/src/androidTest/java/kr/urbanmood/vision/F2NativeDeviceTest.kt)는 주행 프레임과 세로 방향 입력에서 실제 세 모델을 실행했고, 데스크톱 기준과 입력·출력·합성 지도 픽셀 차이가 0이었다. 객체 검출은 [별도 네이티브 검사](../../app/src/androidTest/java/kr/urbanmood/vision/OrtObjectDetectorDeviceTest.kt)로 확인했다. 이 검사는 배포 경로의 계산 정합이며 새 장면의 분류 정확도나 S25+ 성능을 뜻하지 않는다.

공개한 [최적화 전 원장](android-f2-039/parity-before-optimization.json), [최적화 후 원장](android-f2-039/parity-after-optimization.json), [네이티브 검사 결과](android-f2-039/native-parity-test.txt)에 주행·세로 방향을 포함한 9개 입력의 정합 결과를 남겼다.

최종 메모리 정책을 적용한 뒤에도 같은 실제 입력으로 [네이티브 정합 검사](android-f2-039/native-parity-final.json)를 다시 통과했다. 모델 입력·출력과 F2 합성 지도 차이는 0이었다. 최종 모델 파일 해시와 실행 결과는 이 원장과 [제품 경로 측정 원장](android-f2-039/product-final.json)에 함께 기록했다.

관측격자 확대의 효과도 분리했다. 같은 주행 프레임·기본 분할·객체 박스로 밝은 면적을 측정하면 320격자에서는 9.77%, 원본640격자에서는 11.76%였다. 같은640격자의 F2 결과는 11.50%였다. 따라서 밝은 영역 증가 전체를 모델 개선으로 해석하지 않는다. [격자 비교 결과](android-f2-039/observation-grid-diagnostic.tsv)와 [검사 코드](../../app/src/test/java/kr/urbanmood/vision/F2ObservationGridDiagnosticTest.kt)가 모델 변화와 관측 해상도 변화를 나누어 기록한다.

## 처리 비용

같은 Windows CPU ONNX Runtime 조건에서 n320, n640, s640, C320의 추론 중앙값은 각각 18.82ms, 83.43ms, 110.20ms, 19.11ms였다. 디코딩·전처리·융합은 포함하지 않았고 다른 작업의 부하도 통제한 제품 벤치마크가 아니다. 휴대폰이나 Pleos 차량 성능으로 인용하지 않는다. 해상도 확대와 추가 모델 실행은 정확도뿐 아니라 실제 단말 비용과 함께 판단한다.

초기 원본격자 통합 실행에서는 RGB 후처리가 병목이었다. 타원형 최소·최대 연산을 행별 이동 구간으로 나누고, Gaussian 가중치·반사 인덱스를 재사용하도록 바꿨다. 픽셀별 float 누적 순서와 임계값은 유지했다. [최적화 전 참조 구현과 비교 검사](../../app/src/test/java/kr/urbanmood/vision/SemanticContrastKernelParityTest.kt)에서 무작위·경계·실제 주행 RGB의 마스크·통계·영역 목록이 모두 일치했다.

공개한 최적화 전·후 정합 원장의 `pipelineMs`에는 입력 파일 대조·SHA 계산·계측·기록을 하는 wrapper 작업이 섞여 있다. 이 시간을 제품의 분석 속도로 제시하지 않는다.

별도 [제품 경로 측정](android-f2-039/product-final.json)은 Android 15 x86_64 에뮬레이터에서 `AppServices(context).vision.analyze`를 wrapper 없이 호출했다. 실제 전처리·모델 추론·융합·객체 검출·빛과 하늘 관측을 포함하며, 촬영·영상 디코딩·화면 표시·전체 촬영 구간 누적은 제외한다.

|---|---:|
| 새 분석기의 첫 호출 | 2.117초 |
| 재사용 호출 중앙값 | 1.652초 |
| 재사용 호출 범위 | 1.597–2.153초 |
| 분석 직후 프로세스 PSS 표본 | 약 167–179MiB |
| 분석기 종료 직전 / 직후 PSS | 약 172.7 / 148.0MiB |

첫 호출은 지연 모델 로딩과 자산 검사를 포함하지만 OS 캐시·JIT·열 상태를 초기화한 측정은 아니다. PSS는 각 분석 직후의 표본이며 순간 최대 메모리가 아니다. 이 값은 S25+나 Pleos·실차 성능, FPS를 나타내지 않는다. 실기기의 지연·최대 메모리·취소 응답은 후속 검증 항목이다.

이전 제품 경로 검사에서는 모델 세션을 유지하는 동안 메모리가 크게 남았다. ORT의 `setCPUArenaAllocator(false)`와 `setMemoryPatternOptimization(false)`를 함께 적용해 세션별 재사용 버퍼 정책을 바꿨다. 모델·정밀도·해상도·임계값은 유지했고, 최종 정합 재검사를 통과해 이 정책을 채택했다. [변경 전 기록](android-f2-039/product-before-memory-policy.json)도 보존한다. 변경 전 지연 측정은 호스트 빌드와 겹친 비통제 실행이므로 최종 값과의 속도 향상 비율을 계산하지 않는다. 두 옵션을 함께 바꾼 실험이므로 효과를 한 옵션에만 귀속하지 않는다.

## 다음 개선과 기록 원칙

복합 구성 평가에서도 실패하면 실패한 규칙과 원인을 보존한다. 미사용 보조 평가 결과를 보고 다시 조정했다면 그 자료는 이후 개발 자료로 분류한다. 창문·작은 간판에는 원본 영역 확대와 부분 주석의 보강을 검토하고, 사람·차량에는 객체 검출기의 별도 비교가 필요하다. 모델 자동 주석을 사람 정답으로 표현하거나, 실제 측정하지 않은 광원 정확도·감성 정확도를 채우지 않는다.

[학습 코드·실제 가중치와 실행 기록](../../models/semantic/finetuning03/README.md), [실험별 평가와 사전 판정](finetuning03/README.md), [모델 해시](finetuning03/model-hash-manifest.json)를 함께 제공한다. 최종 보고서에는 실패한 후보도 포함하고, 채택 결과와 앱 통합 여부를 구분한다.

## 원본을 먼저 확인한 시각 검수 — 2026-10-25

사용자 주행 영상의 정해진 시점에서 원본 관찰을 먼저 기록하고, 기존 모델과 F2의 이름을 가린 출력 지도를 교차 검수했다. 판단을 기록한 후 모델 정체를 확인했다. 같은 개발 영상에 대한 AI 정성 검수이며, 독립 시험이나 사람 정답 기반 정확도 측정으로 제시하지 않는다.

F2는 일부 밤하늘·흐린 하늘·나뭇가지 사이 하늘의 누락을 줄였다. 반면 특정 외벽과 트럭 일부를 간판으로 잘못 분류하는 범위가 늘었다. 요금소 개구부의 노을 하늘 누락, 창문과 간판 혼동, 낮 도심 차도를 보도로 분류하는 문제는 남았다. 따라서 기존 제한적 수치 개선을 전반적인 인식 문제의 해결로 해석할 수 없다.

실제 모델 클래스와 표시 마스크도 대조해 주요 누락이 그림 표시 오류가 아님을 확인했다. 기존 영역 보호 규칙은 기존의 잘못된 분류도 유지할 수 있다. 별도 객체 탐지의 박스 표시와 앱에서 관측으로 채택하는 기준 역시 구분했다. 상세 사례, 검토자 이견과 구체적인 후속 실험은 [직접 검수 추가 기록](VISUAL_REVIEW_20261025.md)에 남겼다. 이번 검수로 학습이나 결합 규칙을 변경하지 않았으며, 검수 결과와 후속 개선 방법을 [설계 보고서](../product/DrivingMood_이태현_개발보고서.pdf)에도 반영했다.
