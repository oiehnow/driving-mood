# 서로 다른 모델 계열 비교

현재 휴대폰 0.3.9의 F2는 YOLO 계열의 입력 크기와 가중치를 나누어 결합한 구성이다. 서로 다른 구조의 모델을 결합한 결과는 아니다. 같은 계열에서 창문 누락과 간판 과확장이 함께 남아, 장면 분류와 물체 경계를 서로 다른 모델에 맡길 수 있는지 실제 주행 입력으로 비교했다.

이번 비교는 추가 학습 전의 후보 선별 실험이다. 기존 개발 영상에서 고정한 동일 RGB 입력을 사용하고, 각 공식 체크포인트의 전처리를 기록한 뒤 결과를 원본 입력 좌표로 복원했다. 이미 검토한 영상을 재사용했으므로 독립 시험이 아니다. 원본과 결과의 AI 시각 검수이며, 사람이 완성한 정답 마스크가 없어 정확도나 전체 개선율을 산출하지 않았다.

## 실제 실행한 모델의 장단점

| 모델·체크포인트 | 맡길 수 있는 역할 | 실제 입력에서 확인한 장점 | 확인한 실패·제약 | 현재 판단 |
|---|---|---|---|---|
| SegFormer B0 · ADE20K | 하늘·건물·도로 등 장면 분할 | 주간의 넓은 하늘과 건물 구분, 일부 차량 분리 | 검토 입력에서 창문 분류 없음. 작은 간판과 밤의 구조 경계 누락 | 경량 장면 모델 후보로 유지 |
| SegFormer B1 · ADE20K | 장면 분할·구조 보조 | 일부 상점·옥상 간판을 추가 포착, 요금소 창문 일부 분리 | 야간 발광 창문은 해결하지 못함. 어두운 하늘을 건물로 오인 | B0와 함께 장면·비용 비교 후보 |
| Mask2Former Swin-T · ADE semantic | 마스크 단위 장면 분할 | 건물·차량·일부 간판의 영역 후보 제공 | 모든 검토 입력에서 창문 분류 없음. 방음벽·어두운 영역을 건물로 묶는 오류 | 비교 기준으로 보존; 현재 가중치의 비상업 조건 별도 확인 필요 |
| OneFormer Swin-T · ADE20K | 하늘·건물·물체와 간판 후보 | 일부 야간 상점·머리 위 표지판을 Mask2Former 실행보다 더 포착 | 창문 분류 없음. 교통표지와 상점 간판을 함께 잡아 조명·활기로 곧바로 사용할 수 없음 | 서로 다른 계열 결합의 장면 기준 후보 |
| DeepLabV3 MobileNetV3-Large · COCO/VOC | 지원 클래스의 사람·차량 영역 | 주간의 가까운 승용차 일부를 분리 | 요금소를 열차(train)로 크게 오인해 차량 제외 영역에 포함, 보행자 누락. 하늘·창문·간판·도로 및 truck 전용 클래스가 없는 체크포인트 | 현재 체크포인트의 전체 장면 교체는 부적합 |
| PIDNet-S · Cityscapes | 도로 장면의 효율적인 분할 | 주간 일부 도로·하늘 영역이 합리적 | 노을 장면을 차량으로 크게 오인. 모든 입력에 적용한 해상도 확대 대조에서도 해결되지 않음. 창문·상점 간판 클래스 없음 | 현재 입력의 기본 분류기로 채택하지 않음 |
| SAM2.1 Tiny | 주어진 위치의 정밀한 경계 | 검출 박스보다 차체를 좁게 분리하는 사례 확인 | 잘못 붙은 ‘간판’ 이름은 고치지 못함. 창문 프롬프트가 없으면 창문을 새로 발견하는 실험이 되지 않음 | 검증된 차량 후보의 경계 보조로 결합 실험 |
| MobileSAM | 작은 인코더로 프롬프트 분할 | 일부 차량 경계를 보완; 이번 CPU 실행에서 SAM2.1 Tiny보다 짧은 추론 관측 | 작은 객체·가지 사이 하늘 누락, 잘못된 분류 이름을 그대로 물려받는 문제 | 모바일 후보이지만 Android 실행 검증 필요 |

모델 하나의 실패를 해당 구조 전체의 한계로 일반화하지 않는다. 학습 자료, 클래스 목록, 입력 크기와 가중치가 함께 작용한다. 특히 Mask2Former의 배포 전처리는 384×384이고 OneFormer는 짧은 변 512의 비율 유지 입력이므로, 이번 차이를 구조 자체의 우위로 단정할 수 없다. CPU와 GPU, 입력 크기가 다른 실행 시간을 섞어 속도 순위를 만들지도 않는다.

## SAM은 무엇을 보완했는가

SAM2.1 Tiny와 MobileSAM에는 결과를 보기 전에 고정한 검출 박스 및 기존 분할 영역의 박스를 전달했다. 모델이 제공한 이름과 SAM이 정리한 모양을 구별했다. 낮은 신뢰도의 보행자 후보는 진단용으로만 유지했으며 실제 앱 사람 관측 성공으로 올려 세지 않았다.

차체에 맞춘 마스크는 박스에 함께 들어 있던 도로·배경을 덜 가리는 데 유용했다. 반면 기존 모델이 건물이나 빛나는 탑을 간판이라고 부른 경우에는 SAM도 그 잘못된 이름을 유지한 채 경계만 또렷하게 만들었다. 간판 후보와 SAM 결과의 단순 합집합은 오히려 잘못된 조명 점수를 강화할 수 있다. 창문 후보 자체가 없던 입력은 ‘SAM 창문 인식 실패’로 채점하지 않았다.

실행에는 기존 Ultralytics의 SAM 구현을 사용했지만 가중치와 구조는 공식 SAM2.1·MobileSAM이다. 실행 라이브러리가 같다는 이유로 YOLO 모델인 것은 아니다. 공식 체크포인트의 키를 엄격하게 확인해 로드했으며, 원본 저장소 실행기와의 수치 동일성까지 검증한 것은 아니다.

## 서로 다른 계열을 실제로 결합한 H1 실험

OneFormer 장면 분할에 YOLO 차량 검출과 SAM2.1 차체 마스크를 결합했다. 결합 결과를 생성하기 전에 조건을 고정했다. 검출 신뢰도 0.5 이상, SAM 영역의 절반 이상이 검출 박스 안에 있고 절반 이상이 OneFormer 차량 영역과 겹칠 때만 후보를 받는다. 서로 다른 차종 판단이 충돌하면 제외하고, 박스 바깥이나 기존 사람·하늘 영역은 변경하지 않는다. 기존 차량 영역을 지우지 않는 보수적인 추가 방식이다.

**결과는 부분적인 경계 보완과 새로운 오류가 함께 나타나 기본 구성으로 채택하지 않았다.** 야간 승용차의 후미등과 외곽 일부는 차량 제외 영역에 들어왔지만, 주간 승용차의 범퍼 아래 그림자와 대형 트럭 아래의 도로·전경도 차량 영역으로 늘어났다. 보호한 사람·하늘 픽셀은 그대로였으나, 그 조건만으로 경계의 정확성이 보장되지는 않았다.

F2, OneFormer 단독, H1을 함께 비교했다. F2와 H1의 큰 차이 대부분은 OneFormer로 기본 장면 모델을 바꾼 데서 생겼고, SAM을 추가한 효과는 작고 혼재했다. 픽셀이 늘어난 양을 정확도 향상으로 계산하지 않았다. 추가 추론 비용을 정당화하려면 차량 몸체와 그림자를 구분한 정답, 차량광 제외 후 조명 점수 변화, 새로운 영상에서의 오탐 검증이 필요하다. 다음 경계 규칙은 별도 실험으로 고정해 비교하며 이번 실패 결과를 덮어쓰지 않는다.

## 차량 탑재로 이어지는 개선 방법

1. **영역의 이름과 경계를 따로 평가한다.** 하늘·건물·간판의 의미는 장면 모델, 사람·차량 후보는 검출기, 필요한 객체의 경계는 SAM 계열에 맡기는 조합을 비교한다. ‘SAM이 잘 잘랐다’와 ‘이름을 맞혔다’를 같은 성공으로 취급하지 않는다.
2. **모델 간 합의가 없는 픽셀은 무조건 합치지 않는다.** 차량 검출과 장면 분할이 겹치는 후보에서 경계 보정을 시도하고 사람·하늘을 덮어쓰지 않도록 제한한다. 기존 F2뿐 아니라 결합에 쓰는 장면 모델 단독 결과와도 비교해, 복잡도 증가만 생긴 경우를 탈락시킨다.
3. **남은 핵심 문제는 발광 창문이다.** 건물 안 밝은 부분을 전부 창문으로 간주하지 않는다. 창문·간판·반사·차량광·가로등을 구분한 검수 자료를 마련하고, 경계와 실제 밝기·색을 별도로 평가한다. 도로 표지판을 상점 조명으로 세는 오류도 독립 항목으로 관리한다.
4. **새 영상 단위로 시험 자료를 분리한다.** 같은 영상의 인접 프레임을 학습·검증에 흩뿌리지 않는다. 후보를 고른 뒤 노을·여명·낮·밤·우천 등 새로운 영상에서 규칙을 고정해 누락과 오탐을 다시 확인한다.
5. **최종 구성은 실제 단말 비용으로 정한다.** 무거운 모델을 모든 프레임에 실행하는 방식뿐 아니라 대표 프레임 분할과 중간 프레임 추적을 비교한다. ONNX 등 변환 후 동일 입력 결과, Android·Pleos 메모리·지연·발열을 확인해야 앱 채택을 결정할 수 있다. 이번 PC 추론은 그 검증을 대신하지 않는다.

현재 배포 APK의 모델 구성은 바뀌지 않았다. 이번 실행은 구조가 다른 후보의 실제 장단점을 확인한 연구 결과이며, 추가 학습이나 차량에서의 성능 향상을 완료한 것으로 표현하지 않는다.

## 공식 출처와 활용 조건

- [SegFormer](https://github.com/NVlabs/SegFormer): 공식 모델과 클래스 구성 참고, 실제 ADE20K B0/B1 가중치 실행. 공식 이용 조건은 비상업 연구·평가 범위로 확인했다.
- [Mask2Former](https://github.com/facebookresearch/Mask2Former): 원본 구조와 모델 출처. 구현 코드의 MIT 조건과 모델 가중치의 CC BY-NC 4.0 조건을 구별한다.
- [OneFormer](https://github.com/SHI-Labs/OneFormer) · [실행한 공식 모델 카드](https://huggingface.co/shi-labs/oneformer_ade20k_swin_tiny): 원본 코드와 모델 카드 MIT 표기. 데이터 이용 조건은 별도 검토한다.
- [Transformers](https://github.com/huggingface/transformers): Apache-2.0, SegFormer·Mask2Former·OneFormer의 추론 구현과 공식 전처리 사용.
- [torchvision](https://github.com/pytorch/vision): BSD-3-Clause, DeepLabV3 MobileNetV3 공개 API와 공식 체크포인트 사용.
- [PIDNet](https://github.com/XuJiacong/PIDNet): MIT 원본 구현, 저자가 안내한 Cityscapes 가중치 사용. 데이터·가중치 조건을 코드 라이선스만으로 대체하지 않는다.
- [SAM2](https://github.com/facebookresearch/sam2) · [MobileSAM](https://github.com/ChaoningZhang/MobileSAM): 공식 가중치로 실제 경계 분할, Apache-2.0 고지 보존. [Ultralytics](https://github.com/ultralytics/ultralytics) 실행 구현은 AGPL-3.0이다.
- [SAM3](https://github.com/facebookresearch/sam3): 조사만 수행, SAM License와 가중치 접근 조건 적용. Apache-2.0로 표기하지 않는다.
- [EfficientSAM](https://github.com/yformer/EfficientSAM) · [EfficientTAM](https://github.com/yformer/EfficientTAM) · [EfficientViT](https://github.com/mit-han-lab/efficientvit) · [SegMAN](https://github.com/yunxiangfu2001/SegMAN): 공식 구현·배포 경로 조사, Apache-2.0 고지 확인. 이번 실행 모델 목록에는 포함하지 않는다.

원본 영상, 가중치, 입력·출력 해시, 프롬프트, 클래스 목록과 실행 환경은 비공개 실험 기록에 보존했다. 외부 가중치를 이 저장소에 재배포하지 않는다. [기존 실험과 실패 기록](MODEL_IMPROVEMENT_LOG.md) · [기존 F2 원본 대조 검수](VISUAL_REVIEW_20261025.md)
